# 방법론 실험 노트 — 설치 안내

이 폴더 안 파일들을 그대로 GitHub 저장소에 올리고 GitHub Pages로 배포하면 됩니다.
아래 순서를 그대로 따라 하시면 됩니다.

## 1) 로컬 확인 (선택)

브라우저에서 `index.html`을 더블클릭해서 열어보면 미리 확인할 수 있습니다.
(단, `fetch`가 필요한 기능은 없어서 파일을 직접 열어도 대부분 잘 작동합니다.)

## 2) GitHub 저장소 만들기

1. github.com 에서 새 저장소(Repository) 생성
   - 이름: 원하는 대로 (예: `method-book`)
   - **Public**으로 설정 (GitHub Pages 무료 사용을 위해 — 대신 아래 3번에서 비밀번호로 잠급니다)
2. 이 폴더의 파일 전체(`index.html`, `style.css`, `app.js`, `manifest.json`, `sw.js`, `icon-192.png`, `icon-512.png`)를 저장소에 업로드
   - GitHub 웹사이트에서 "Add file → Upload files"로 드래그해서 올리면 됩니다.

## 3) 비밀번호 잠금 걸기 (StaticCrypt)

저장소를 Public으로 만들기 때문에, 페이지 내용 자체를 암호화해서 비밀번호 없이는 못 보게 만듭니다.

터미널(명령 프롬프트)에서:

```bash
npx staticrypt index.html -o index.html --short
```

실행하면 비밀번호를 입력하라고 물어봅니다. **16자 이상의, 남들이 추측 못 할 비밀번호**를 입력하세요.
완료되면 `index.html`이 암호화된 버전으로 바뀝니다 (원본은 `staticrypt-config.json`에 설정이 남으므로, 원본을 다른 이름으로 백업해두는 걸 권합니다).

이 암호화된 `index.html`을 그대로 GitHub에 올리면, 방문자는 비밀번호를 입력해야만 내용을 볼 수 있습니다.

> 참고: `npx`가 없다면 Node.js(nodejs.org)를 먼저 설치해야 합니다.

## 4) GitHub Pages 켜기

1. 저장소 페이지에서 **Settings → Pages**
2. Source를 "Deploy from a branch"로, Branch를 `main`(또는 `master`) / `/(root)`로 설정 후 저장
3. 몇 분 후 `https://[내계정].github.io/[저장소이름]/` 주소로 접속 가능

## 5) 데이터는 어디에 저장되나요?

이 도구는 서버 없이, **접속한 브라우저의 저장공간(localStorage)**에만 기록을 남깁니다.
- 같은 컴퓨터의 같은 브라우저로 계속 접속하면 기록이 유지됩니다.
- 브라우저를 바꾸거나(크롬→엣지), 다른 기기에서 열면 빈 상태로 보입니다.
- 브라우저에서 "사이트 데이터 삭제"를 하면 기록도 사라집니다.

**따라서 주기적으로 왼쪽 하단의 "⭳ 백업" 버튼을 눌러 파일로 저장해두시길 권합니다.**
나중에 다른 기기에서 쓰거나 데이터가 사라졌을 때, "⭱ 복원" 버튼으로 그 백업 파일을 다시 불러올 수 있습니다.

## 6) 완료 표시 관련

이 도구 안에서는 "완료(스프레드시트로 옮겼는지)" 체크만 합니다.
실제 실행 결과(아이템/기간/투입/수익/판단/교훈)는 이 도구가 아니라 별도의 구글 스프레드시트에 직접 기록하시면 됩니다.
